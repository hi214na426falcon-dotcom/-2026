# 週次バックテストの自動実行（Mr.2 Gold）

毎週土曜の朝、パソコンが自動で次の作業を行い、結果を Discord に送ります。

1. XAUUSD の1分足ヒストリーを最新にする（`automation/fetch_history.py`）
2. MT4 のストラテジーテスターで4種類のバックテストを実行する
3. 分析ツール（`backtest/analyze_mt4.py`）でウォークフォワード・モンテカルロ・推奨ロットを計算する
4. 結果を Discord に送る（詳しいレポートはファイルで添付）

| テスト名 | 期間 | スプレッド | 目的 |
|---|---|---|---|
| `5y` | 直近5年 | 34 | 長期の安定性＋ウォークフォワード（IS 12か月 → OOS 3か月） |
| `recent12m` | 直近12か月 | 34 | 今の相場で勝てているか（稼働判断の基準） |
| `since_v2` | 2026/04/06 〜 | 34 | v2.0 リリース後＝本当の意味での未知の期間 |
| `5y_stress` | 直近5年 | 60 | スプレッドが広がっても耐えられるか |

- 終了日は「HFM サーバー時間で前日」です。土曜の朝なら金曜までのデータでテストします。
- テストの種類や期間は `automation/config.json` の `runs` で変更できます。

---

## 0. 用意するもの

- Windows パソコン（土曜の朝に電源が入っていて、サインインしている状態）
- HFM の MT4（普段使っているものとは別に、テスト専用のコピーを作ります）
- HFM の**デモ口座**（Mr.2 Gold はデモ口座なら認証不要です）
  - 本番は Top-Up Bonus 口座なので、デモも同じ口座タイプで作るのがおすすめです。
- Python 3.10 以上
- Discord の Webhook URL

---

## 1. テスト専用の MT4 を用意する（初回のみ）

**なぜ別の MT4 が必要か**：MT4 は同じフォルダのものを2つ同時に起動できません。
普段の MT4 を自動で起動しようとすると、開いている画面が前に出るだけでテストが始まりません。
また、本番トレード中の MT4 に影響を与えないためにも、テスト専用のコピーを作ります。

1. 今の MT4 のインストールフォルダを探す
   - デスクトップの MT4 のアイコンを右クリック →「ファイルの場所を開く」
   - 例：`C:\Program Files (x86)\HFM Metatrader 4`
2. そのフォルダを丸ごとコピーして、`C:\MT4_Backtest` という名前で貼り付ける
   - `Program Files` の中だと、ポータブルモードでファイルを保存できません。必ず `C:\` の直下などに置いてください。
3. **ポータブルモード**で1回起動する
   - `Windows キー + R` を押し、次を入力して OK
     ```
     "C:\MT4_Backtest\terminal.exe" /portable
     ```
   - ポータブルモードでは、設定・EA・ヒストリーがすべて `C:\MT4_Backtest` の中に保存されます。
4. HFM の**デモ口座**でログインする
   - 「ファイル」→「取引口座にログイン」
   - サーバーは `HFMarketsSV-Demo Server 2`（口座のメールに書かれたもの）
   - **「パスワードを保存」にチェック**を入れる
5. EA を入れる
   - `Mr2_gold_v2.0(HFMonly).ex4` を `C:\MT4_Backtest\MQL4\Experts\` にコピーする
   - MT4 の「ナビゲーター」で「エキスパートアドバイザ」を右クリック →「更新」
   - **このコピーでは、チャートに EA を付けないでください**（テスト専用です）。
6. 「ツール」→「オプション」→「チャート」タブ
   - 「ヒストリー内の最大バー数」と「チャートの最大バー数」を `9999999999` にする → OK
7. ストラテジーテスターの初期設定（1回だけ画面で設定します）
   - 「表示」→「ストラテジーテスター」→ エキスパートアドバイザで `Mr2_gold_v2.0(HFMonly)` を選ぶ
   - 「エキスパート設定」→「テスト」タブ →「初期証拠金」を **884 USD** にする
     - デモ口座が USD 建てなので、テスターも USD で計算します。
     - 140,000 円 ÷ 158.4 円 = 883.84 USD。運用資金（`capital_jpy`）や為替（`usdjpy`）を変えたら、ここも合わせて直してください。
     - 自動実行のたびにレポートの初期証拠金を確認し、設定と 2% 以上違うと Discord に🟡の警告が出ます（MT4 の起動設定では初期証拠金を指定できないため、ここで1回設定する必要があります）。
     - **注意**：前回のスクリーンショットのテストは、初期証拠金が **140000 USD**（約2,200万円）になっていました。
       これだと実際の資金の約158倍で計算されるため、ドローダウン（%）やリスクが実際よりずっと小さく見えます。
   - 同じ画面の「パラメーターの入力」タブで、初期ロットなどを実際の運用と同じにする
     →「保存」を押し、`C:\MT4_Backtest\tester\mr2.set` という名前で保存する
   - **「ビジュアルモード」のチェックは外したまま**にする（自動実行はこの画面の設定を引き継ぐ可能性があり、チェックが入っていると5年テストがとても遅くなり時間切れになります）
   - 1週間ほどの短い期間で1回テストを実行し、設定が覚えられたことを確認する
8. **MT4 を閉じる**（自動実行の時間に開いていると失敗します）

## 2. Python を入れる（初回のみ）

1. <https://www.python.org/downloads/> から Windows 版をダウンロードしてインストール
2. インストール画面の最初で **「Add python.exe to PATH」にチェック**を入れる
3. 確認：コマンドプロンプトで `py --version` と入力し、`Python 3.1x.x` と表示されれば OK

## 3. このツールをパソコンに置く（初回のみ）

GitHub のこのリポジトリで「Code」→「Download ZIP」→ 展開して、例えば `C:\mr2-tools` に置きます（`git clone` でも可）。
自動実行はこのフォルダを使うので、**後からフォルダを移動しないでください**（移動したら手順6をやり直す）。

## 4. 設定ファイルを作る（初回のみ）

1. `automation\config.example.json` をコピーして、同じフォルダに `config.json` という名前で保存
2. メモ帳で `config.json` を開き、主に次の項目を確認・変更する

| 項目 | 内容 |
|---|---|
| `mt4_dir` | `"C:\\MT4_Backtest"`（**`\` は `\\` と2つ重ねて書く**） |
| `server_dir` | デモ口座のサーバー名。`C:\MT4_Backtest\history\` の中にある同じ名前のフォルダに1分足を書き込みます |
| `parameters_file` | 手順1-7で保存した `mr2.set` |
| `spread` | 通常テストのスプレッド（34 = 0.34ドル）。本番の Top-Up Bonus 口座で見える XAUUSD のスプレッドに合わせてください |
| `capital_jpy` / `current_lot` / `usdjpy` | 運用資金（円）・今の初期ロット・ドル円レート |
| `discord_webhook_url` | 結果を送るチャンネルの Webhook URL |

- Webhook URL の作り方：Discord のチャンネルの「⚙ チャンネルの編集」→「連携サービス」→「ウェブフック」→「新しいウェブフック」→「ウェブフックURLをコピー」
- `config.json` は Git に登録されない設定になっています。**Webhook URL やパスワードを GitHub やチャットに貼らないでください**（URL を知っている人は誰でもそのチャンネルに投稿できます）。
- 各項目の説明は `config.example.json` の「_」で始まる行に書いてあります。

## 5. 初回は手動で実行する

コマンドプロンプトを開いて、ツールのフォルダに移動します。

```
cd C:\mr2-tools
```

**① 設定の確認（MT4 も Discord も動かさない）**

```
py automation\run_backtests.py --config automation\config.json --dry-run
```

MT4 に渡す設定と、Discord に送る予定の文面が表示されます。「警告」が出たら、その内容を直してください。

**② 短いテストを1本だけ本番実行**

```
py automation\run_backtests.py --config automation\config.json --only recent12m
```

MT4 が自動で開き、テストが終わると自動で閉じます。**その間は MT4 を触らないでください**。
Discord に結果が届き、`reports\日付\` フォルダにレポートが保存されれば成功です。

**③ 全部のテスト**

```
py automation\run_backtests.py --config automation\config.json
```

5年分の1分足テストは1本で数十分〜数時間かかります。

その他のオプション：`--skip-history`（ヒストリー更新をしない）、`--only 5y since_v2`（指定したテストだけ）。

## 6. 毎週の自動実行を登録する

ツールのフォルダで次を実行します（1回だけ。何度実行しても上書きされます）。

```
powershell -ExecutionPolicy Bypass -File automation\register_task.ps1
```

- タスク名 `Mr2Gold_WeeklyBacktest`、**毎週土曜 09:07**（パソコンの時刻）に `automation\run_weekly.bat` を実行します。
- MT4 は画面のあるアプリなので、「ユーザーがログオンしているときのみ実行」で登録します。
  **土曜の朝はパソコンの電源を入れ、サインインしたまま**にしてください（画面ロックは OK、サインアウトは NG）。
- 予定時刻に電源が切れていた場合は、次にパソコンを起動したときに実行されます。
- すぐに試す：`powershell -Command "Start-ScheduledTask -TaskName Mr2Gold_WeeklyBacktest"`
- 実行の記録：`reports\last_run.log`（メモ帳で開けます）
- 登録を消す：`powershell -ExecutionPolicy Bypass -File automation\register_task.ps1 -Remove`

## 7. Discord に届く内容

```
🟡 判定: ロットを下げる
・直近（recent12m）の PF 1.24 が 1.3 未満
推奨ロット（ストレス以外で最も慎重な値）: 0.01（資金 140,000円・運用ロット 0.01）

[5y｜2021-10-16〜2026-10-16｜スプレッド34]
PF 1.45 / 純損益 +123,456円 / DD 12.3%（含み損込み 21.0%） / シャープ 1.20 / WF 合格 / 推奨ロット 0.01
取引 2,345 回　前週比（2026-10-10）: PF -0.02 / 純損益 +1,234円 / DD +0.4pt / 推奨ロット +0.00
（以下、テストごと）
```

| 色 | 判定 | おもな条件（`config.json` の `alerts` で変更可） |
|---|---|---|
| 🔴 赤 | 稼働停止を検討 | 直近12か月の PF が 1.1 未満、または最大DD が 25% 超 |
| 🟡 黄 | ロットを下げる | 直近の PF が 1.3 未満・DD が 20% 超・PF が前週から 0.2 以上低下、ウォークフォワードが「合格」以外、PF 1.0 未満のテストがある、推奨ロットが今のロットより小さい、テスターの初期証拠金が設定の資金と違う（含み損・ロスカットのリスクを確認できないため） |
| ⚪ 灰 | 保留（テストの失敗を確認） | テストが失敗した（MT4 が開いたままだった等）。**EA の成績が悪いという意味ではありません**。直近12か月のテストが失敗したときも、成績を確認できないので灰色になります |
| 🟢 緑 | このまま稼働 | 上のどれにも当てはまらない |

- DD は「決済済みの残高ベース」と「テスターの含み損込み」の大きい方で判定します（テスターの初期証拠金が設定と違うときは、含み損込みの値は使いません）。
- 金額は円換算です（USD 口座の場合は `usdjpy` で換算）。
- テストごとの詳しいレポート（Markdown）が添付されます。同じものが `reports\日付\` にも保存されます。
- 毎週の数値は `reports\history.jsonl` に1行ずつ追記され、前週との差の計算に使います。
- テストが失敗したときや設定ファイルに問題があるときは、灰色（⚪）の失敗通知が届きます。🔴 赤は成績が理由のときだけです。

## 8. うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 「レポートが作成されませんでした」 | いちばん多いのは **`C:\MT4_Backtest` の MT4 が開いたまま**だったケースです。閉じてから再実行してください。<br>ほかに、EA が `MQL4\Experts` にない、ヒストリーがない、デモ口座にログインできない、などが考えられます。<br>`C:\MT4_Backtest\tester\logs\` と `C:\MT4_Backtest\logs\` の日付のファイルにエラーが書かれています |
| EA が見つからない・読み込めない | `config.json` の `expert` が `MQL4\Experts` のファイル名（.ex4 を除く）と完全に同じか確認してください。<br>名前は合っているのに `tester\logs` に EA を読み込めないと出る場合は、名前の「.」や「( )」を MT4 が読み違えている可能性があります。次の順に試してください：<br>① `expert` を `"Mr2_gold_v2.0(HFMonly).ex4"`（.ex4 付き）にする<br>② テスト専用の `C:\MT4_Backtest\MQL4\Experts` の中だけで、.ex4 をコピーして `Mr2_gold_v20_HFMonly.ex4` のように「.」と「( )」のない名前にし、`expert` もその名前にする（デモ口座は認証不要なので、テスト用コピーの名前を変えても問題ない見込みです。普段の MT4 のファイルは変えないでください） |
| 「テスターの初期証拠金 … が設定の資金 … と違います」 | 手順1-7の「初期証拠金」を、表示された設定の資金（例：884 USD）に直してください。直すまでは含み損込みDD%を判定に使わず、🟡になります |
| 「分以内に終了しなかった」 | MT4 にダイアログ（ログイン・更新など）が出て止まっている可能性があります。MT4 を手動で開いて確認してください。<br>5年テストが本当に長い場合は `timeout_minutes` を増やします |
| モデリング品質が 25% 前後・n/a | 1分足チャートを1分足データでテストすると、MT4 の仕組み上こうなります。故障ではありませんが、**結果は楽観的**になりやすいです |
| 不整合チャートエラー・データの抜け | ヒストリーに空白期間があります。`reports\last_run.log` でヒストリー更新のエラーを確認してください。土日の空白は正常です |
| 「ヒストリーの更新に失敗」 | 通信エラーなど。テストは既存のデータで続行し、通知に警告が付きます |
| 設定ファイルの JSON エラー | 表示された行を確認。`\` を `\\` にしているか、行末のカンマが多すぎ・少なすぎでないか |
| Discord に届かない | Webhook URL を確認（チャンネルの Webhook を消すと無効になります）。`reports\last_run.log` にエラーが残ります |

## 9. 限界と注意点

- **MT4 標準のテスターは、1分足から作った疑似ティックで動きます。** スプレッドも固定（34 / 60）で、スリッページもありません。
  1分足スキャルピング EA の結果は、実際より良く出やすいと考えてください。
  Tick Data Suite（有料）を使うと、実ティック・変動スプレッドで検証できて現実に近づきます。
- 分析ツールのウォークフォワードでは、EA 内部のパラメーターは変更できないため、「新規エントリー不可時間帯」だけを最適化します。
  これは「その時間帯に建てた取引を除外する」**近似**で、ナンピンの連鎖が変わる影響は再現できません。
- 2026年以前の期間は、EA の開発時に調整に使われた可能性があります。本当に未知の期間は `since_v2` とデモ・本番の実績だけです。
- 推奨ロットは、モンテカルロの最悪クラスの DD（99%）に安全係数を掛けて計算しています。証拠金維持率・ロスカットは考慮していません。
  Top-Up Bonus 口座のボーナス（クレジット）は、資金に含めずに考えてください（実際に入金した額で判断）。
- テスターの初期証拠金（手順1-7）と、分析に使う資金（`capital_jpy` ÷ `usdjpy`）は別々に設定されます。ツールはずれを検出して警告しますが、直すのは手順1-7の画面だけです。
  ずれたままだと、証拠金不足でナンピンできない・ロスカットされる、といった実際の資金で起きることがテストに出ません。
