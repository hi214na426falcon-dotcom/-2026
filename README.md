# Whimo Web（非公式クローン / Supabase版）

SNSで見つけた「行きたいお店・スポット」を保存して、**地図**や**リスト**で管理・共有できるWebアプリです。
iOS版「Whimo（ウィモ）」がAndroidで使えないため、**リンクを知っていればブラウザで使える**Web版として作りました。

> ⚠️ 本家「Whimo」とは無関係の、個人開発クローンです。将来の正式リリースを見据えた構成にしています。

---

## できること

- 📋 **リスト管理**（複数リストの作成・切替・リネーム・削除）
- 📍 **スポット追加/編集**（名前・カテゴリー・メモ・場所・SNSリンク・訪問済み）
- 🔗 **SNSリンク自動判別**（Instagram / TikTok / X / Googleマップ / 食べログ 等）
- 🗺 **地図表示**（OpenStreetMap・カテゴリー色分けピン・APIキー不要）
- 🔎 **場所検索 / 地図タップで指定**（OpenStreetMap Nominatim）
- 🏷 **カテゴリー絞り込み** ／ ✅ **行った/行きたい**
- 👤 **アカウント（クラウド保存）** … 複数端末で同期
- 👫 **リストの共有** … 相手の**メールを指定した人だけ**が閲覧・一緒に編集
- 📷 **写真アップロード** … 行った場所に写真（Supabase Storageに保存）
- 🧾 **隠し家計簿** … レシート＋使った金額。**ロゴ📍の「7回タップ／長押し」で開く（設定で選択）**。記録ごとに**🔒自分だけ / 👫相手と共有**を選べる
- 🧳 **旅の記録（ルート）＋スライドショー** … GPSでルートを記録、撮った写真を地図上のルートに配置し、最後にスライドショー再生
- 🔗 **リンクで共有（軽量版）** … リスト内容をURLに埋め込む方式でも共有可
- 📱 **PWA対応**（Android Chromeで「ホーム画面に追加」）

**ローカルモード**：Supabase未設定でも、この端末だけで上記の大半（同期・相手との共有を除く）が使えます。

## セットアップ（クラウド機能を使う場合）

### 1. Supabaseプロジェクトを作る（無料・クレカ不要）
1. https://supabase.com にサインアップ → **New project** を作成（リージョンは **Tokyo (ap-northeast-1)** 推奨）。
2. 左メニュー **SQL Editor** → `supabase/schema.sql` の中身をすべて貼り付けて **Run**。
   （テーブル・権限・写真用ストレージ`whimo`バケットが一括で作られます。何度実行してもOK）

### 2. 鍵をアプリに設定
1. Supabaseの **Project Settings → API** を開く。
2. `js/env.js` を編集し、次の2つを貼り付け：
   ```js
   window.WHIMO_ENV = {
     SUPABASE_URL: 'https://xxxxxxxx.supabase.co',   // Project URL
     SUPABASE_ANON_KEY: 'eyJhbGci...',               // anon public キー
   };
   ```
   ※ anon（公開）キーはブラウザに置いても安全です。データは行レベル権限(RLS)で保護されます。

### 3. ログイン方法の設定
- **Authentication → Providers → Email** を有効化。
- テストを簡単にするなら **Authentication → Sign In / Providers → "Confirm email" をオフ**にすると、登録後すぐログインできます（本番運用時はオン推奨）。
- アプリを開き、メニュー（左上☰）→「ログイン / 新規登録」からアカウント作成。

これで複数端末の同期・共有・写真・家計簿が有効になります。

## 使い方メモ

- **共有する**：リスト一覧で対象リストの「⋯」→「共有」→ 相手のメールを追加。相手は**同じメールでログイン**するとそのリストが見えます（一緒に編集可）。
- **隠し家計簿を開く**：上部の 📍 ロゴを**7回タップ**または**長押し**（メニュー→設定で切替）。
- **お金の公開範囲**：記録ごとに「🔒自分だけ／👫相手と共有」を選択。`自分だけ`は共有相手にも見えません。
  ※レシート画像は現状**アップした本人のみ**閲覧可（金額・メモは共有設定に従う）。共有画像が必要なら次段階で対応します。
- **旅の記録**：「🧳 旅」タブ →「▶ ライブ記録を開始」で移動ルートをGPS記録。記録中に「📷 いまの場所で写真を追加」でルート上に写真を配置。「⏹ ゴール」で終了 →「▶ スライドショーを再生」で地図ルート＋写真を再生。「📍 スタート／ゴールを指定」でGPSを歩かず2地点だけの記録も可（「🛣 道に沿ったルート」で実際の道路に沿ったルートを取得＝無料のOSRM、キー不要）。
  ※旅の記録は現状**この端末に保存**（ルート＝localStorage、写真＝IndexedDB）。クラウド同期は次段階で対応します。
- **スライドショーの演出**：設定で**切替効果（フェード / ズーム / スライド）**と**表示時間**を選択。再生画面で **🎵 BGM**（端末の音楽ファイル）を設定、**⬇ 動画に書き出し**（webm）も可能。
- **旅ごとの合計金額**：旅の詳細画面で出費を記録すると合計が出ます（家計簿的な用途）。
- **旅のクラウド保存・共有**（ログイン時）：旅の詳細で「☁ クラウドに保存」→「👫 共有（メール招待）」。相手は「🧳 旅」タブの「☁ クラウドの旅」から**閲覧専用**でルート＋スライドショーを見られます。

## ローカル実行 / 公開

ES Modules と地図/検索APIを使うため、`file://` ではなく**ローカルサーバー経由**で開いてください。
```bash
python3 -m http.server 8000   # → http://localhost:8000
```
**公開（Androidで開く）**：ビルド不要の静的サイトなので、**GitHub Pages / Netlify / Vercel / Cloudflare Pages** にそのまま置けます。
発行URLをAndroid Chromeで開き「ホーム画面に追加」でアプリ化。

```

  data.js             データ層ルーター（ローカル⇄クラウドを切替）
  localAdapter.js     ローカル保存の実装（localStorage）
  cloudAdapter.js     Supabaseの実装（DB/Storage）
  supa.js             Supabaseクライアント・認証
  env.js              接続設定（各自で記入）
  store.js            ローカルのデータモデル
  config.js           カテゴリー定義・プラットフォーム判定
  geo.js              住所検索・逆ジオコーディング
  share.js            共有リンクのエンコード/デコード
  map.js              Leaflet地図
  img.js              画像の圧縮（アップロード前）
```

## データ設計（Supabase）

- `lists` / `list_members`（共有）/ `spots` / `spot_photos` / `expenses`
- **RLS**でアクセス制御：
  - リストは「オーナー」または「メンバー（招待メール）」のみ閲覧、編集はエディター権限のみ。
  - 家計簿(`expenses`)は `visibility='private'` なら**作成者本人のみ**、`shared` なら共有相手も閲覧。
- **Storage**（バケット `whimo`、非公開＋署名URL）：
  - `photos/<list>/<spot>/…` はリスト閲覧者が表示可能。
  - `receipts/<user>/…` はアップ本人のみ。
